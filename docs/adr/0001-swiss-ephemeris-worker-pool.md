# Swiss Ephemeris runs only on a fixed pool of dedicated worker threads

Swiss Ephemeris keeps mutable global state (ephemeris path, sidereal mode, topocentric position, open files, caches). It is per OS thread only where it is compiled with thread-local storage; upstream disables TLS on macOS (`sweodef.h:86`, `!defined(__APPLE__)`), which our patched source removes. So hora calls it only from a fixed pool of long-lived `std::thread` workers, never from the async runtime or `tokio::task::spawn_blocking`. tokio reuses and retires blocking threads, so a request would inherit the previous request's settings, an exiting thread would leak its files and memory (there is no TLS destructor), and the pool would grow to 512 threads under load on a public service.

## Decision

- **Source:** our fork [secsaba/swisseph](https://github.com/secsaba/swisseph), vendored at tag `v2.10.3bfinal-hora.1` (commit `e041a0077076a574b8411ceee7f24b0733dc56ca`): the official [aloistr/swisseph](https://github.com/aloistr/swisseph) tag `v2.10.3bfinal` plus two patches proposed upstream, TLS on macOS ([aloistr/swisseph#23](https://github.com/aloistr/swisseph/pull/23)) and a `swe_close` fix ([aloistr/swisseph#22](https://github.com/aloistr/swisseph/pull/22)). Never master (SE 3.0 work lands there). Each new upstream tag gets the unmerged patches rebased onto it as a new `-hora.N` tag; once upstream releases both, vendor upstream directly and drop the fork. The commit is recorded next to the vendored source, and `flake.nix` fetches the ephemeris data files from the same commit. TLS stays on.
- **Pool size:** N workers from runtime config, default `std::thread::available_parallelism`, on Linux (production is Debian) and macOS (development). There is exactly one pool per process (a process-wide `OnceLock`), and tests use that shared pool rather than building their own. Each worker opens its own ephemeris files and buffers, so memory and file handles grow with N; do not set N far above the core count.
- **Queue:** bounded, length from runtime config (default 4 × N). A full queue or a queue wait over ~2 s returns HTTP 503 with `Retry-After`; the 2 s counts time spent waiting in the queue only, not calculation time. Each job carries that deadline, and a worker drops a job without calling C if its deadline has passed or its reply channel is closed (`is_closed()`), so jobs abandoned by a 503 or a disconnected client do not occupy workers. A calculation that has started always finishes; C calls cannot be cancelled.
- **One trip per chart:** a worker job returns every raw ephemeris value for one moment and place (planets, houses, ayanamsa, the Vedic day's Sun events). Everything derived from longitudes (vargas, nakshatras, dashas) is computed in plain Rust outside the worker.
- **Worker lifecycle:** `swe_set_ephe_path` once at startup, with the path from hora's config, `HORA_EPHE_PATH` (it closes open files, so calling it per request would defeat the file cache). Before every chart, set the sidereal mode and topocentric position explicitly. `swe_close` only at shutdown: it closes the cached `.se1` files, so calling it per request would defeat the file cache (it also resets the sidereal mode to Fagan/Bradley, which the per-chart setting above already covers). The pool lives in a static, which Rust never drops, so `main` calls an explicit `shutdown()`: each worker finishes its current job, calls `swe_close` and exits.
- **Misuse is unrepresentable:** the `extern "C"` functions are private to the wrapper crate; the only public entry point to the ephemeris is the pool's async `calculate(request)`, beside the pure `julian_day` date conversion below. The worker-side handle is `!Send`/`!Sync`. No Rust API exists for house system 'I' (Sunshine; writes non-TLS `static saved_sundec`, `swehouse.c:636`), `SE_SIDBIT_PREC_ORIG` (leaves `astro_models` changed for later calls), or `swe_get_library_path` (non-TLS `static Dl_info`). The one exception to "only on the workers" is `swe_date_conversion` (a `swe_julday`/`swe_revjul` round trip) in request validation and the public `julian_day`: pure date arithmetic that reads no library state (`swedate.c`), run on the caller so a bad request is rejected before it is queued.
- **Ephemeris data:** the pinned files (`sepl_12.se1`, `sepl_18.se1`, `semo_12.se1`, `semo_18.se1`, `sefstars.txt`) cover 1200–2399 AD. Outside that range the library silently falls back to its less precise Moshier model instead of failing. So the worker checks the flags each call returns, and a result without `SEFLG_SWIEPH` fails the chart with an error; this also catches a wrong path or a missing file.
- **Request dates:** a request carries the birth time as entered (local clock time, in its calendar) and its UTC offset: stated (whole seconds, −12:00 … +14:00), local mean time (longitude / 15 hours, exact, never rounded to the minute) or local apparent time. Validation turns stated and local mean time into UT; local apparent time needs the equation of time from the ephemeris, so the worker applies `swe_lat_to_lmt` as the first step of the same trip. It uses only the thread-local `swed`, so the worker rule holds; it returns no ephemeris flags (`swe_time_equ` drops them), so a Moshier fallback cannot be detected there, and cannot happen inside the validated window. Dates are validated before queueing; a bad one is `InvalidInput`, never `Ephemeris`. The caller states the calendar (Gregorian or Julian, no per-country switch table). `swe_date_conversion` rejects impossible dates such as 30 February, but it treats both calendars as proleptic, so two bounds are explicit: a Gregorian date before 1582-10-15 (the calendar did not exist yet; enter such births as Julian), and a UT moment outside the files' window, Julian 1200-01-01 0h up to (not including) Gregorian 2399-12-31 23h UT, less two days at each end. The library picks the file from the moment in TT, about 9 minutes after UT here; from 2400-01-01 TT it looks for a 2400 file and falls back to Moshier unless `sepl_18` happens to be open, so the window ends an hour early. The two days keep the Sun event searches (from 25 h before the birth to about 29 h after) inside the files, since `swe_rise_trans` returns no flags to check. The year 1200..2399 check before the round trip only keeps `swe_revjul`'s `(int)` casts in range; the window decides. The window is checked on local apparent time read as local mean time; the two days also cover the difference, at most about 16 minutes. The worker calculates for the Julian day that validation computed, corrected by the equation of time for local apparent time.
- **Environment:** the server refuses to start if `SE_EPHE_PATH` is set, because the library lets it override the path argument (`sweph.c:1327`).
- **Crash handling:** one process; a crash in the C library takes the process down and the supervisor restarts it. Subprocess isolation is not worth its cost until crashes are observed.
- **Verification:** a test runs concurrent charts with different ayanamsas, each of which must match its single-threaded reference value. CI runs it on Linux (Ubuntu); on macOS it runs in local development.

## Considered options

- **`spawn_blocking` per chart**: rejected for the reasons above.
- **`TLSOFF` and one worker everywhere**: simplest and identical on every platform, but caps each process at one chart at a time. Rejected because Linux TLS works and production is Linux.
- **Upstream `v2.10.3bfinal` unpatched, with N = 1 forced on macOS**: the previous decision. Rejected once the TLS patch was written and tested: the fork is two small commits, and it gives the same thread model, and the concurrency test, on every platform we run.
